# Design decisions

## Brand translation

The [Brand Bible v2.4](https://brand.basedcode.dev/) describes a working developer identity
with purple depth, white type and purposeful movement. The wallpaper is an authored abstract
field, not a simulated screen, a product illustration or a borrowed game aesthetic.

Published Core `#472458` is used instead of incidental CSS values in the guide. The exact
official colours are recorded in `src/design.json`. Derived dark shades below Carbon keep
editor sidebars subtly separate. Violet is decorative; readable labels use white, secondary
text, or Lumen on a sufficiently dark background.

The procedural field is periodic in time. Its crest travels while broad layers change
position, giving a soft, visible cycle without animating text or flashing the whole canvas.
The upper strip stays dark for the transparent bar. Both wallpapers are text-free.

## Functional colour exceptions

| Meaning | Colour | Bright variant |
|---|---|---|
| Errors and removals | `#DF929E` | `#EDB0B9` |
| Success and additions | `#A5BEA2` | `#C1D5B8` |
| Warnings and types | `#D8BF8C` | `#E9D4AC` |
| Functions and information | `#ADB4D8` | `#CCD0EB` |
| Parameters and hints | `#9DBFCA` | `#BED8DE` |
| Keywords | `#C789D2` | `#DEB0E5` |

Orange `#DCA78C` and brown `#C0A18B` complete the native semantic palette. These are restrained,
readable implementation colours rather than official brand extensions. Ordinary shell activity
uses Lumen, avoiding accidental error-red indicators inherited from the stock bar template.

## Integration choices

Theme-section overrides replace only sections with intended differences. Stock font and spacing
sections remain generated by Omarchy. The installer does not write `shell.json`; this preserves
the existing widget arrangement and transparent bar preference.

The VS Code override is generated from the installed native template with a small explicit
patch set: opaque focus indicators, Core selections, and dark secondary buttons with white text.
This corrects concrete contrast failures while retaining upstream token coverage.

No scripts run from the runtime theme itself. Asset generation and QA tools live in the separate
source package. This allows Git-installed theme staging to regenerate terminal/Lua configs normally.
